
"Whenever <this creature> deals [combat] damage to a creature, tap that
creature [and it doesn't untap during its controller's next untap step]"
(untargeted damage-recipient referent acted on by a resolver)
--------------------------------------------------------------------------
Cards: Kashi-Tribe Warriors, Kashi-Tribe Elite, Kashi-Tribe Reaver,
Matsu-Tribe Birdstalker / Decoy / Sniper, Orochi Ranger, Frostwalk Bastion,
Queen of Ice (tap + freeze); Mercurial Kite, Neko-Te (tap half). Same class as
Toxin Sliver / Stinkweed Imp (destroy) and Obelisk Spider (counter).

- "That creature" is the damage RECIPIENT, an untargeted referent of the
  trigger event (CR 608.2k), parsed as TargetFilter::EventTarget. The trigger
  has no chosen target, so ability.targets is EMPTY at resolution.
- Main-path hydration (effects::hydrate_event_context_targets) fills targets
  only for TriggeringSource, never EventTarget. Every resolver that reads only
  ability.targets / live_object_targets therefore silently does nothing for an
  EventTarget subject. Symptom: the trigger goes on the stack and resolves,
  and nothing happens.
- Fix pattern (resolver-local, gated on ability.targets.is_empty() so a chosen
  or delayed-pinned target still wins, CR 603.7c):
  targeting::resolve_event_referent_permanents(state, filter, source_id) -
  incarnation-checked (CR 400.7, via the damage ledger's target_incarnation)
  referents that are still phased-in battlefield permanents. Used by
  tap_untap.rs (SetTapState), prepare.rs (BecomePrepared), and effect.rs
  (GenericEffect with affected: EventTarget, e.g. the CantUntap rider).
  Destroy uses the same idea via is_pure_event_context_filter.
- When another effect kind has the same symptom with an EventTarget subject,
  add the same gated arm in its resolver using this helper; don't add
  EventTarget to hydration (shared by ~50 effect kinds, no incarnation check).
- "doesn't untap during its controller's next untap step" expires on the
  AFFECTED object's controller's untap step (CR 502.3,
  layers::prune_controller_untap_step_effects), not the ability controller's.
- Still open: Mercurial Kite / Neko-Te parse the rider's "that creature" as
  ParentTarget, so the freeze installs nothing for them.
- Test: tests/integration/kashi_tribe_damage_tap_freeze.rs (attacker and
  blocker sides, dead recipient, blinked recipient, untap-step expiry).


"Prevent the next N damage that would be dealt to any target this turn"
(declared "any target" damage prevention shield minting a target slot)
--------------------------------------------------------------------------
Cards: Aven Redeemer, Healing Salve, Alabaster Wall, etc.

- "Any target" means target creature, player, or planeswalker (CR 115.4).
- Spells or abilities using "target" to identify an object or player choose it
  as a target (CR 115.1d).
- In phase-engine, `extract_target_filter_from_effect` suppresses `TargetFilter::Any`
  by default to prevent spurious target selection prompts on broadcast / untargeted
  effects (CR 115.1, issue #824).
- Only specific effect kinds where `TargetFilter::Any` represents an actual player-chosen
  target are exempted (`DealDamage`, `EachSourceDealsDamage`).
- For `PreventDamage`, a target slot must be built when:
  `recipient_scope == EffectScope::Single`, `damage_source_filter.is_none()`, and
  `amount == PreventionAmount::Next(_)` or `amount_dynamic.is_some()`.
- Untargeted mass prevention effects (Fog, Holy Day: `amount == PreventionAmount::All`)
  and source-scoped prevention effects (Awe Strike, Maze of Ith: `damage_source_filter.is_some()`)
  must NOT mint an "any target" recipient slot.
- Untargeted prevention test fixtures and definitions must specify `recipient_scope: EffectScope::All`;
  `EffectScope::Single` designates a declared recipient slot, which intentionally installs nothing
  at resolution if no target was chosen (CR 115.6).
- Tests: crates/engine/tests/integration/declared_prevent_recipient_scope.rs,
  crates/engine/src/game/triggers.rs unit tests.


"If no cards are in that graveyard, [effect]" / Self-flip with inherited target
(graveyard referent tied to target card's owner; self-referential flip)
--------------------------------------------------------------------------
Cards: Nezumi Graverobber ("{1}{B}: Exile target card from an opponent's
graveyard. If no cards are in that graveyard, flip this creature.")

- CR 108.3 + CR 404.1: "that graveyard" refers to the graveyard from which the
  targeted card was chosen (the owner of the targeted object), not the active
  player's or controller's graveyard.
- Evaluated via `PlayerScope::ParentObjectTargetOwner` in `QuantityExpr::PerZone {
  zone: ZoneRef::Graveyard, player: PlayerScope::ParentObjectTargetOwner, filter: TargetFilter::All }`.
  `parent_target_owner(ability, state)` looks up the owner of the targeted card
  (`ability.targets.first()`).
- In `FlipPermanent` (CR 710.4), when an activated ability chains into a sub-ability
  (`FlipPermanent { target: TargetFilter::SelfRef }`), `ability.targets` contains
  the parent's declared target (the exiled card). `effects/flip_permanent.rs` must
  resolve targets via `super::resolved_effect_object_ids(state, ability, &target)`
  and filter out the source ID when it only arose from declared targets that don't
  target the permanent (mirroring `transform_effect.rs`).
- Tests: crates/engine/tests/integration/kamigawa_flip_cards.rs
  (nezumi_graverobber_flips_when_targeted_graveyard_is_emptied,
  nezumi_graverobber_does_not_flip_when_cards_remain_in_targeted_graveyard,
  nezumi_graverobber_flips_even_if_another_player_has_cards_in_graveyard),
  crates/engine/src/game/effects/flip_permanent.rs unit test
  (self_flip_ignores_inherited_foreign_object_target), and
  crates/engine/src/parser/oracle_nom/condition.rs unit test
  (test_parse_no_cards_in_that_graveyard).


"When this creature enters, target opponent reveals their hand and you choose a nonland card from it. Exile that card. / When this creature leaves the battlefield, return the exiled card to its owner's hand."
(Two-trigger linked exile-and-return with hand origin and return to hand)
--------------------------------------------------------------------------
Cards: Tidehollow Sculler, Mesmeric Fiend

- CR 607.1 + CR 607.2a + CR 406.6 + CR 610.3: Two-trigger linked exile-and-return
  ability design where the ETB trigger exiles a chosen card from a revealed hand
  via a sub-ability (`Effect::RevealHand` chaining into `Effect::ChangeZone` to `Exile`),
  and the LTB trigger returns "the exiled card to its owner's hand" (`Effect::Bounce`
  or `Effect::ChangeZone` to `Zone::Hand`).
- `detect_etb_exile_ltb_return` / `trigger_is_etb_exile_pending_duration`:
  The ETB exile is not at root; it lives in a sub-ability under `RevealHand`.
  `ability_has_exile_pending_duration` descends through `sub_ability` to locate
  the unstamped `ChangeZone` / `ChangeZoneAll` to `Zone::Exile`.
- `trigger_is_ltb_return_shape` / `change_zone_return_has_no_entry_modifiers`:
  Accepts return-to-hand shapes (`Effect::Bounce` with no or Hand destination, or
  `Effect::ChangeZone` to `Zone::Hand`) targeting `TrackedSet` or `ExiledBySource`
  without entry modifiers, matching return-to-battlefield shapes (Journey to Nowhere,
  Oblivion Ring, Worldgorger Dragon).
- `apply_etb_exile_ltb_return` / `stamp_etb_exile_pending_duration`:
  Stamps `Duration::UntilHostLeavesPlay` on the ETB exile sub-ability node (and root),
  so `zone_pipeline.rs` installs `ExileLinkKind::UntilSourceLeaves { return_zone: from }`
  (with `from == Zone::Hand`).
- When the permanent leaves the battlefield, `check_exile_returns` moves the exiled card
  from `Zone::Exile` back to `Zone::Hand` (CR 400.7 / CR 108.3 owner's hand).
- Tests: `crates/engine/src/parser/oracle_tests.rs`
  (`tidehollow_sculler_etb_exile_gets_until_host_leaves_duration`),
  `crates/engine/tests/integration/tidehollow_sculler_exile_return.rs`
  (`tidehollow_sculler_returns_exiled_card_to_hand_when_it_leaves_play`,
  `mesmeric_fiend_returns_exiled_card_to_hand_when_it_leaves_play`,
  `tidehollow_sculler_with_no_nonland_cards_in_opponents_hand`).


"... unless that player says "<phrase>"" / "you may say "<phrase>". If you do, [effect]"
(spoken phrase as the cost of an unless-payment or optional payment; Un-card actions)
--------------------------------------------------------------------------
Cards: Rod of Spanking (unless that player says "Thank you, sir. May I have
another?"), Impounding Lot-Bot (you may say "INCARCERATE!" in a robot voice),
Infernius Spawnington III, Esq. (you may say "I'm here."). Same class, not yet
built: Ow, Loose Lips, Carnivorous Death-Parrot ("sacrifice unless you say its
flavor text"), Toy Boat's cumulative upkeep.

- CR 118.12a: "[Do something] unless [a player does something else]" means the same
  as "[A player] may [do something else]. If [that player] doesn't, [do something]."
  Saying the phrase IS the payment: AbilityCost::SayPhrase { phrase }. It moves no
  resources, so it rides the existing pipelines unchanged: resolution-time
  unless-payments (WaitingFor::UnlessPayment + PayUnlessCost) and "you may pay ...
  If you do" optional payments (Effect::PayCost + DecideOptionalEffect). Do not add a
  parallel "say" effect or WaitingFor.
- Opt-in gate: only a player who enabled Un-card actions (GameState.un_actions,
  GameAction::UnAction(SetEnabled)) can say a phrase. For everyone else the prompt
  never opens and the "unless" branch simply happens (resolution_unless payers are
  skipped by un_actions::cost_requires_unavailable_speech; an optional "you may say"
  is infeasible via effects::optional_effect_is_infeasible -> costs::can_pay_resolution).
- Parser: extract_resolution_unless_pay_modifier (oracle_effect/mod.rs) reads
  "unless <payer> says "..."" -- the quoted span is masked there, so the phrase is
  read from the ORIGINAL text at the same byte offset. parse_cost_resource_ast
  (imperative.rs) reads the imperative `say "..." [in a <x> voice]`.
- Tests: crates/engine/tests/integration/un_card_actions.rs.


"Gotcha -- If an opponent [does X], you may say "Gotcha!" When you do, return this
card from your graveyard to your hand."
(opponent behavior the engine cannot observe; Un-card actions)
--------------------------------------------------------------------------
Cards: Touch and Go, Cardpecker, Laughing Hyena, Stop That, Number Crunch,
Creature Guy, Deal Damage, Kill! Destroy!, Save Life, Spell Counter, Name Dropping.

- Modeled as TriggerMode::GotchaSaid + TriggerDefinition.gotcha_condition (typed
  GotchaCondition: Physical(PhysicalTell) / SaysAnyOf{words} / SaysNumber /
  SaysWordInGraveyardCardName). The trigger functions from the zone its effect
  returns the card from (graveyard), except Name Dropping (battlefield, returns
  "that card" = the TriggeringSource of GameEvent::GotchaSaid.returns).
- "When you do" is the CR 603.12 reflexive trigger: calling "Gotcha!" emits
  GameEvent::GotchaSaid, which the card's own trigger consumes; the return goes on the
  stack like any trigger.
- The engine cannot see a face being touched, so the OPPONENT performs the gesture
  from the Un-actions menu (UnAction::PerformTell). un_actions::open_gotcha_offers
  then opens a window (un_actions.gotcha_offers) for every opted-in opponent whose
  Gotcha ability matches. The window closes at the next ordinary game action; the
  client additionally shows the Gotcha! button for only 2 seconds. Windows open only
  at a Priority boundary so the reflexive trigger can reach the stack at once.
- The menu itself is derived by the engine (un_actions.menu = refresh_menu) from the
  Gotcha abilities in play, so it never offers a gesture no card responds to.
- Parser: parser/oracle_un.rs (split_gotcha_line / gotcha_trigger), dispatched at the
  top of the oracle.rs line loop. American punctuation puts the comma inside the quote
  ("guy,") -- trailing punctuation is trimmed from the watched words.
- Swallow check: a Gotcha trigger satisfies Optional_YouMay (trigger_tree_has_optional)
  and Condition_If (gotcha_condition) without extra AST flags.
- Tests: crates/engine/tests/integration/un_card_actions.rs.
